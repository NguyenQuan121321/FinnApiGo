### A. Correctness bugs (silent failures)

**A1. Fix the §5 body-size limit no-op** (`cmd/server/main.go`, `internal/routes/routes.go`)
- Bug: `router.Use(maxBytes…)` is called *after* `routes.Register()` already registered every route, so Gin never attaches it. The "global" limit currently does nothing.
- Fix: add `MaxRequestBodyBytes int64` to `routes.Deps`, apply `r.Use(...)` at the **top** of `Register()` before any route is registered. Remove the post-hoc `router.Use` in `main.go`.

**A2. Wire the 6 dead config knobs** (defined + commented as working, read by no code). All use the existing `store.Store` (`IncrBy` fixed-window counters) so they become multi-instance correct for free once RedisStore lands.

- **`RequireEmailVerified` (§2)** — in `AuthService.Login`, when true and `!user.IsEmailVerified`, return `ErrEmailNotVerified` (→403). Default `false` preserves current behavior and all existing tests. *Documented policy decision* (the prompt explicitly flags this as needing team sign-off); I'll surface it prominently in CHANGELOG so it's easy to flip.
- **`MaxLockoutMultiplier` (§3 exponential backoff)** — `recordFailedLogin` scales lockout as `base * min(recentLockoutCount, multiplier)`. Recent-lockout count tracked via `store.IncrBy("lockouts:<uid>", 24h)` so repeat offenders get progressively longer lockouts.
- **`LoginPerAccountMax`/`LoginWindow` (§3 per-account login limiter)** — in `Login`, `store.IncrBy("login:acct:<email>", LoginWindow)`; over cap → `ErrRateLimited` (new sentinel →429). Throttles one account targeted from many IPs.
- **`RegisterPerIPMax`/`RegisterWindow` (§2 registration velocity)** — add `IP` to `RegisterInput` (matches the existing `LoginInput{ip,ua}` pattern); enforce in `Register` via `store.IncrBy("reg:ip:<ip>")`.
- **`OTPSendPerUserMax`/`OTPSendWindow` (§5 OTP per-user limiter)** — give `MFAService` a `store` field (+ param in `NewMFAService`); enforce in `SendOTP` keyed by userID.
- **`LoginCaptchaAfterFails` (§3 adaptive CAPTCHA)** — inject `CaptchaVerifier` into `AuthService` (already a service-package interface), add `CaptchaToken` to `LoginInput`. In `Login`: if `store.IncrBy? Get("loginfail:<ip>")` ≥ threshold, require the captcha verifier to pass (else `ErrCaptchaRequired` →400). Increment counter on the bad-password path. *(The 7th knob, `Audit.BufferSize/FlushBatch` async audit, is **deferred** per your choice.)*

- **New sentinels** in `services/errors.go`: `ErrRateLimited`, `ErrCaptchaRequired`. Wire both into `statusForError` (→429, →400).
- **Harden §1.7 duplicate-key check** — replace `isMySQLDup`'s fragile string-matching (`"Duplicate entry"`/`"1062"`) in `services/auth_service.go` with `errors.As(err, &*mysql.MySQLError)` + `Number==1062`, exactly as §1.7 specifies and as `repositories/errors.go` already does correctly. Add a test using a fake error wrapping `*mysql.MySQLError` for both email and username branches.
